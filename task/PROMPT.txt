实现一个本地账号关联服务，把两个身份源的外部身份绑定到同一内部账号。身份源用本地HMAC签名断言模拟，协议由本题定义，不接真实账号。

请从空目录实现以下可运行工具。环境为 Windows、Python 3.12、仅CPU；不使用Docker或真实外部服务。除题面明确允许的cryptography外只用标准库。输入样例、模拟组件和测试数据由你在项目内构造，不存在另行提供的附件。

核心要求：
1. 外部身份的唯一键为issuer与subject，邮箱只作展示，不能据此自动合并。发起关联必须同时证明当前内部账号的近期登录状态与待绑定身份的所有权；挑战绑定内部账号、目标issuer、浏览器会话及到期时间，完成后一次性消费。
2. 两个独立进程可能把同一外部身份同时绑定到不同内部账号；数据库必须保证只有一个胜者，关联写入、挑战消费与审计事件同事务提交。原请求丢响应后可凭相同request_id查询既有结果，换参数复用request_id必须拒绝。
3. 解绑必须保留至少一种可用登录方式；关联、解绑与禁用账号并发时以数据库提交顺序线性化。账号禁用提交后启动的新操作不能成功，旧挑战不得在重新启用后自动恢复有效。提供可注入时钟和崩溃点。

必须覆盖的验收场景：同邮箱不同主体、交换浏览器会话、并发抢绑、双重解绑最后两个入口、提交前后崩溃和重启重试；用真正的两个进程与屏障复现，不以线程锁代替跨进程一致性。

交付源代码、README、样例及自动化测试。提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口；cases.json可引用项目内源文件或二进制样例。输入输出schema、错误码及未写明的非安全性细节自行设计并完整说明，不能放宽上述要求。测试必须断言具体结果、状态或证据，不能只打印成功；固定种子可重放。所有操作局限在项目测试目录和本机模拟服务。
